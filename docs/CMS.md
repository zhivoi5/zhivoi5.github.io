# Управление сайтом «Текстиль Дизайн»

Сайт статический: страницы собираются из файлов в `src/content/`. Эти файлы редактируются
в админке **Sveltia CMS** по адресу `/admin/`. Каждое сохранение — коммит в репозиторий
на GitHub; после коммита сайт пересобирается и публикуется автоматически.

На сайте нет базы данных, серверного кода и паролей. Войти в админку может только тот,
у кого есть доступ к репозиторию на GitHub (рекомендуется включить двухфакторную защиту).
Личные токены в админке отключены (`auth_methods: [oauth]`).

## Что можно менять

| Раздел админки | Что внутри | Файлы |
|---|---|---|
| Наши работы | Проекты салона: название, дата, порядок, описание, фотографии, разделы каталога, «Скрыть с сайта» | `src/content/works/*.md`, фото — `src/assets/works/` |
| Каталог | 9 разделов: тексты, фото раздела, группы и позиции | `src/content/catalog/*.json` |
| Тексты страниц | Главная, Услуги, Выезд дизайнера, Ткани, Наши работы, Лифт-системы, Блэкаут | `src/content/pages/*.json` |
| Контакты и настройки | Адрес, координаты, часы, телефоны, почта, оплата, рассрочка | `src/content/settings/*.json` |

Ограничения, которые защищают сайт:
- разделы каталога нельзя удалить или создать из админки — от них зависят адреса страниц;
- якорь позиции (`organza`, `blackout`…) проверяется: только латиница, цифры и дефис.
  У существующих позиций его не меняют — на него ведут ссылки;
- первый телефон в списке — основной: он в шапке и на всех кнопках «Позвонить».

## Как добавить работу в «Наши работы»

1. Откройте `https://<домен>/admin/` → «Войти через GitHub».
2. «Наши работы» → «Новая работа».
3. Заполните название и дату. При желании — порядок в галерее, место и описание.
   Без адресов и имён клиентов.
4. В «Фотографии» добавьте снимки и для каждого коротко опишите, что на нём.
   Фото с телефона можно загружать как есть: админка сама уменьшит их до 2400 px и сохранит в WebP.
5. Отметьте разделы каталога, к которым относится работа.
6. «Сохранить». Через 1–3 минуты работа появится на сайте на странице `/works/`.

**Порядок.** Работы с номером идут первыми: 1 — самая верхняя. Работы без номера стоят после них,
от новых к старым по дате.

**Скрыть работу**, не удаляя её: включите «Скрыть с сайта (черновик)» и сохраните. Чтобы вернуть —
выключите. Удалить работу совсем — кнопка удаления в карточке работы.

Ссылка «Наши работы» есть в меню на всех страницах. Пока нет ни одной опубликованной работы,
страница показывает сообщение «Здесь скоро появятся реализованные проекты салона» (текст меняется
в «Тексты страниц» → «Наши работы»), закрыта от поисковиков и не входит в карту сайта. После первой
опубликованной работы она начинает индексироваться, а в подвале появляется ссылка на раздел.

**Только реальные фотографии выполненных заказов.** Иллюстрации и сгенерированные
изображения в этот раздел не добавляются.

## Как вернуть прошлую версию

Вся история изменений хранится в GitHub. Любой коммит можно откатить
(«Revert» на странице коммита) — сайт пересоберётся с прежним содержимым.

## Проверки при каждой сборке

`npm run build` не опубликует сайт, если найдёт: формы, цены, слова «бесплатно» и «гарантия»,
ссылки на мессенджеры, страницы без основного телефона или с несколькими h1, битые ссылки и якоря.
Предупреждает (но не останавливает), если каталог отличается от исходного списка владельца
или на страницах остались временные фото-заглушки.

## Подключение перед публикацией (один раз)

Ничего из этого пока не сделано — сайт не опубликован, домен не куплен.

1. **Репозиторий.** Создать приватный репозиторий на GitHub и загрузить в него проект
   (ветка `main`).
2. **Вход через GitHub (бесплатно).** Развернуть
   [Sveltia CMS Authenticator](https://github.com/sveltia/sveltia-cms-auth) на Cloudflare Workers
   (бесплатный тариф) и создать OAuth App в настройках GitHub с адресом этого воркера.
   Секрет приложения хранится только в воркере, не на сайте.
3. **Настройка админки.** В `public/admin/config.yml` заменить `OWNER/REPO` на репозиторий,
   а `base_url` — на адрес воркера.
4. **Хостинг и сборка.** Выбрать хостинг статических файлов и настроить сборку
   GitHub Actions (бесплатно): на каждый коммит — `SITE_URL=https://<домен> npm run build`
   и выгрузка папки `dist/`.
5. **Фото.** Заменить временные заглушки (сборка перечисляет страницы, где они остались):
   положить файлы с именами из `src/data/media.mjs` в `src/assets/media/`.

## Локальная работа без входа

На компьютере разработчика: `npm run dev`, затем открыть
`http://localhost:4322/admin/index.html` в Chrome или Edge и выбрать
«Работать с локальным репозиторием» → корневую папку проекта. Изменения сохраняются прямо
в файлы, коммит делается вручную.
